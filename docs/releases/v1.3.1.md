# Hardware Workbench v1.3.1

Hardware Workbench v1.3.1 是一次修复版：修掉「从旧版本升级上来、第一次开机就丢设置」的缺陷、
浏览器端「网络串口」那一行四个操作全坏的缺陷，把连接/断开/发送失败时用户读到的英文正文换成
与两端一致的中文；同时发布 gcode-sender 0.8.0（默认暂停/取消指令）到插件市场。

## 在线模式

打开：<https://tydwdh.github.io/serial_tool/>

在线版使用最新版 Chrome 或 Edge 即可运行。连接本机串口时，点击“添加设备”，在浏览器弹窗中
选择设备并授权。

## 重点变化

- **工作台配置不再被误判为损坏**：`schema_version` 改名之前写下的 `workspace.json`（只用历史键
  `version` 声明版本）在本版之前读不出来 —— 解析失败被当成“配置损坏”，文件被隔离、回落到默认值，
  面板布局 / 选中端口 / 波特率 / 主题一夜回到初始状态。现在这类文件正常读出（磁盘格式未变，
  写出的仍是 `schema_version`）。
- **浏览器端「网络串口」那一行修好了**：连接、重连、断开、发送此前四件事全坏，根因是同一个端口
  有两种名字（`host:port` 与 `network://host:port`），而“这个名字是不是已注册的网络端口”散在六处、
  用了三种规则。现在收敛成一条判定加一个规范形。**桌面端行为一字未变**。
- **失败文案中文化**：连接 / 断开 / 发送失败此前把强类型错误提前压成字符串，用户读到
  `transport operation failed: port is not connected: COM3` 或整句英文；现在两端都是同一句
  「串口 COM3 未打开（可能已断开，请重连）」。桌面端最后 9 处后台任务出口、插件错误、录制文件
  创建失败一并接上同一套中文映射器，并去掉夹在中英文之间的 `AppError` 分类前缀。
- **重连循环里一条从来没生效过的判定**：`contains("would block")` 换成读类型化错误的 `kind`
  （只认 `WouldBlock`）。**用户可见的变化只有文案**：串口重连硬失败不再带英文框架，网络重连
  失败从 `io error: …` 变成 `操作超时：…`。当前没有任何失败因此从“立即放弃”变成“重试”。
- **插件：gcode-sender 0.8.0**（插件市场同步在售）：默认设置改为开箱即用的 Marlin 配置 ——
  成功匹配 `ok`、错误匹配 `FAILED`、运行中匹配 `echo:busy: processing`，暂停/取消默认发
  `N1 !M410 S0*69`（Marlin quickstop：`!` 前缀 + 行号 + 校验和，`xor8("N1 !M410 S0") = 69`）。
  **注意**：默认值只对“从未写过该键”的安装生效，已存过值的安装不会被改动。
- **加固三处**：发布构建开启整数溢出检查（此前按回绕静默算错）；自更新解压时遇到越界 zip 条目
  改为先记日志再跳过；Lua 主机的正则缓存不再永久泄漏。
- **工程内务**（不影响使用）：把“睡够 500ms 就断言异步结果”这类测试随机红改成等真条件的有界
  等待，接进两条此前只能手工跑的回归，删掉死码与重复实现、拆掉最长的几个函数，
  wasm clippy 覆盖扩到全部能在 wasm32 上编译的工作区成员。

## 桌面版下载

Windows x64：

- `HardwareWorkbenchSetup.exe`：安装版。
- `hardware-workbench-app.zip`：便携版。
- `SHA256SUMS.txt`：Windows 发布文件校验值。

Ubuntu 22.04+ x86_64：

- `hardware-workbench_1.3.1_amd64.deb`：系统安装包。
- `SHA256SUMS-linux.txt`：Linux 安装包校验值。

## 注意事项

- Web Serial 需要 Chrome/Edge，并受浏览器、HTTPS/localhost、用户手势和设备驱动限制。
- 在线版使用浏览器存储和下载，不具备桌面端原生文件路径和原地自动更新能力。
- 卸载会删除用户配置与插件设置（不保留），这是刻意行为。
- macOS 不受支持（无专用代码、CI 与发布包）。
- 本地 Web 开发请使用 `trunk serve --release`；不带 `--release` 会运行 Debug WASM，性能会明显下降。
