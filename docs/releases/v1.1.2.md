# Hardware Workbench v1.1.2

Hardware Workbench v1.1.2 增强了插件管理和 G-code Sender 工作流，并修复了 Windows 发布包资源同步与便携包构建问题。

## 重点变化

- G-code Sender 升级至 `0.7.0`，支持跳过 M110 行号同步。
- 可配置设备“运行中”匹配规则，收到运行中反馈时继续等待而不误判为完成。
- 可配置暂停和取消时直接写入串口的原始指令，不追加行号、校验和，也不等待 ACK。
- 默认在 G-code 作业末尾追加 M2；ACK 超时和设备重传处理改为停止发送，避免设备已执行但 ACK 丢失时重复执行。
- 插件管理页的启用/禁用操作改为明确事件，操作结果会持久化到工作区配置。
- 禁用插件后仍可编辑其设置，重新启用后配置直接生效。
- 修改插件或主题后，Windows 构建会重新同步运行时资源。
- Windows 便携 ZIP 改用系统自带 tar 生成，避免 CI 压缩步骤卡住。

## 下载

Windows x64：

- `HardwareWorkbenchSetup.exe`：安装版。
- `hardware-workbench-app.zip`：便携版。
- `SHA256SUMS.txt`：Windows 发布文件校验值。

Ubuntu 22.04+ x86_64：

- `hardware-workbench_1.1.2_amd64.deb`：系统安装包。
- `SHA256SUMS-linux.txt`：Linux 安装包校验值。

## Ubuntu 安装与运行

安装阶段需要一次系统权限：

```bash
sudo apt install ./hardware-workbench_1.1.2_amd64.deb
```

安装完成后，可以点击应用菜单中的 `Hardware Workbench`，或执行：

```bash
hardware-workbench-app
```

以上运行方式都使用当前普通用户。不要执行 `sudo hardware-workbench-app`。

如果打开 `/dev/ttyUSB0` 或 `/dev/ttyACM0` 时出现 `Permission denied`：

```bash
sudo usermod -aG dialout $USER
```

注销并重新登录后即可再次打开串口。
