# Hardware Workbench v1.3.0

Hardware Workbench v1.3.0 把桌面端与浏览器端的行为对齐到同一份判定上：同一段输入在两端、
在"点一次发送"和"开着周期发送"之间不再给出不同结果；同时修掉浏览器端中文显示、发送历史
排版和一批 Dock 拖拽问题。

## 在线模式

打开：<https://tydwdh.github.io/serial_tool/>

在线版使用最新版 Chrome 或 Edge 即可运行。连接本机串口时，点击“添加设备”，在浏览器弹窗中
选择设备并授权。

## 重点变化

- 周期发送与手动发送共用同一份 HEX 解码与换行规则。**行为变化**：多行 HEX 现在每个周期投
  一帧（与点一次发送一致），不再每行一帧；纯空白文本不再被静默当成发送成功。
- 浏览器端 `Ctrl+Enter` 发送此前是死键位，现在与桌面端走完全相同的路径。
- 浏览器端终端与日志里的中文不再显示为豆腐块（等宽字体族缺少中文回退）。
- 发送器「历史」弹层恢复完整排版：标题与条数、占满宽度的过滤框、定高行、单条删除、
  两步「清空全部」；过滤框从此支持 `re:`。
- 所有搜索入口统一支持 `re:` 前缀正则，非法写法会明确提示"已按字面量搜索"。
- 破坏性操作改为两步确认：「恢复默认布局」「恢复所有默认设置」「终端/日志清空」。
- 设备响应匹配统一为三形态（`re:<regex>`、`^行首锚定`、无前缀子串）。**插件作者注意**：
  `ctx.serial.expect("^ok")` 此前是字面量查找 `^ok`，现在表示行首锚定。
- 卸载真正清干净：补上 eframe 的窗口持久化目录、被隔离的损坏配置副本、更新器写在安装目录
  里的残留；清单与代码由一条测试钉在一起。
- 自动更新只认发布时外部固定的 SHA256，不再"下载完自己算一遍跟自己比"。
- Lua 插件运行环境收回 `dofile`、`loadfile`、`load`，`require` 不再按 `package.path` 读盘。
- Dock 拖拽：上下拆分在左右两侧行为一致、最后一个面板被拖走后区域开关失效、途经标签栏误切
  面板、空白处松手误移动、Esc 取消后残留预览矩形等问题修复。
- 浏览器 Lua VM 改为全平台编译，其契约测试现在在宿主平台上直接执行同一份实现。

## 桌面版下载

Windows x64：

- `HardwareWorkbenchSetup.exe`：安装版。
- `hardware-workbench-app.zip`：便携版。
- `SHA256SUMS.txt`：Windows 发布文件校验值。

Ubuntu 22.04+ x86_64：

- `hardware-workbench_1.3.0_amd64.deb`：系统安装包。
- `SHA256SUMS-linux.txt`：Linux 安装包校验值。

## 注意事项

- Web Serial 需要 Chrome/Edge，并受浏览器、HTTPS/localhost、用户手势和设备驱动限制。
- 在线版使用浏览器存储和下载，不具备桌面端原生文件路径和原地自动更新能力。
- 从 v1.2.0 升级时，桌面端「检查更新」可能先报一条以「解析更新信息失败：」开头的错误 ——
  v1.2.0 生成的那份 `update.json` 还没有 `sha256` 字段。本版发布流水线会把该字段写入清单，
  此后升级路径恢复正常；期间可直接下载安装包，不需要清理配置。
- 卸载会删除用户配置与插件设置（不保留），这是刻意行为。
- macOS 不受支持（无专用代码、CI 与发布包）。
- 本地 Web 开发请使用 `trunk serve --release`；不带 `--release` 会运行 Debug WASM，性能会明显下降。
