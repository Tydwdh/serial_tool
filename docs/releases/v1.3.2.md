# Hardware Workbench v1.3.2

Hardware Workbench v1.3.2 修掉两个"看得见却一直没被真正解决"的老问题：**串口拔掉后界面不再一直显示
"已连接"**（空闲期有了设备存活探测），以及**接收区不再把未封存的数据压成一行 `…`**；同时把
自动重连从"只认枚举列表 diff 的一次性尝试"换成了真状态机（退避 / 上限 / 可取消），并按你的
反馈把右上角通知卡片的停留时间减半、给 G-code 插件加了"发送区不是文件就打开文件选择框"。

## 在线模式

打开：<https://tydwdh.github.io/serial_tool/>

在线版使用最新版 Chrome 或 Edge 即可运行。连接本机串口时，点击“添加设备”，在浏览器弹窗中
选择设备并授权。

## 重点变化

- **串口断连真正被发现了**。空闲期此前完全依赖"恰好有一次 I/O 失败"：设备被拔出时驱动不一定
  完成那次挂起的读，于是句柄仍是"活着"的，顶栏一直绿、状态栏一直"已连接"，只有手动重连那次
  open 才失败。现在 Windows 读循环每秒探一次设备存活（连续两次失败才判死），非用户发起的
  断开还会发一条带原因的 `transport.serial.closed` —— 界面立刻变灰并说明原因，而不是等你去做别的动作。
- **自动重连换成真状态机**：按端口记账、退避 0.5s→1s→2s→4s→8s（封顶）、最多 10 次，超限明确报
  "已尝试 10 次"；触发点从"端口重新出现在枚举列表"扩到"枚举变化 **或** 设备失效事件"（设备死了
  但端口还在系统列表里这一类以前完全不触发）；非选中端口同样会重连；顶栏进度不再恒定显示
  `0.0s (1/10)`，取消重连的三处入口统一成一条路径（取消过的端口不会被同一帧又挂回去）。
- **接收区不再压缩数据**：未封存的行此前只显示最后一段、超宽前缀 `…`，而"封存"只在新数据到达时
  发生，于是"收到超过一行的数据后没有下文"就永远停在那个形态上。现在未封存与已封存的行渲染
  相同，长行按行宽折行显示；`merge_window_ms` 只决定后续数据是否并入同一行，不再影响显示。
- **右上角通知卡片的读条时间减半**：提示 1.5s → 0.75s、警告 2s → 1s、错误 4s → 2s（状态栏那行字
  仍按原时长保留）。悬停依旧暂停倒计时，点关闭立即消失。
- **G-code 插件（gcode-sender 0.9.0，插件市场同步在售）**：点「G文件」时，如果发送区里那一行
  打不开（空、G-code 片段、多行程序、写错的路径），直接打开文件选择框，而不是只记一条警告要求
  先清空；能打开的路径仍直接使用，不弹框。取消选择则一行都不发。
- 顺手删掉一段死代码：手动重连里那个"3 秒预算 + 10ms 轮询"的循环，其判据（`WouldBlock`）在这条
  路径上从来没有生产者，实际效果只是把失败结果压在手里最多 3 秒。手动重连现在失败即报，中文原因
  照旧。

## 桌面版下载

Windows x64：

- `HardwareWorkbenchSetup.exe`：安装版。
- `hardware-workbench-app.zip`：便携版。
- `SHA256SUMS.txt`：Windows 发布文件校验值。

Ubuntu 22.04+ x86_64：

- `hardware-workbench_1.3.2_amd64.deb`：系统安装包。
- `SHA256SUMS-linux.txt`：Linux 安装包校验值。

## 注意事项

- Web Serial 需要 Chrome/Edge，并受浏览器、HTTPS/localhost、用户手势和设备驱动限制。
- 在线版使用浏览器存储和下载，不具备桌面端原生文件路径和原地自动更新能力。
- 卸载会删除用户配置与插件设置（不保留），这是刻意行为。
- macOS 不受支持（无专用代码、CI 与发布包）。
- 本地 Web 开发请使用 `trunk serve --release`；不带 `--release` 会运行 Debug WASM，性能会明显下降。
